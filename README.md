# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две сущности, описывающие данные: товар и покупатель, описаны типы для обмена данными с сервером.

#### Тип TPayment
Способ оплаты заказа.

```
type TPayment = 'card' | 'cash';
```

`'card'` — онлайн, `'cash'` — при получении.

#### Интерфейс IProduct
Товар каталога. Структура совпадает с данными, которые приходят с сервера.

```
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

`id` — уникальный идентификатор товара.  
`description` — подробное описание товара.  
`image` — имя файла изображения; полная ссылка получается добавлением его к `CDN_URL`.  
`title` — название товара.  
`category` — категория товара (софт-скил, хард-скил, кнопка, дополнительное, другое).  
`price` — цена в синапсах; `null`, если у товара нет цены и его нельзя купить.

#### Интерфейс IBuyer
Данные покупателя, которые он указывает при оформлении заказа.

```
interface IBuyer {
  payment: TPayment | '';
  email: string;
  phone: string;
  address: string;
}
```

`payment` — выбранный способ оплаты; пустая строка, если способ оплаты ещё не выбран.  
`email` — электронная почта покупателя.  
`phone` — телефон покупателя.  
`address` — адрес доставки.

#### Тип TBuyerErrors
Результат валидации данных покупателя. Ключи - поля `IBuyer`, значения - текст ошибки. Если поле заполнено корректно, соответствующего ключа в объекте нет.

```
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;
```

#### Интерфейс IProductsResponse
Ответ сервера на запрос списка товаров.

```
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

`total` — общее количество товаров.  
`items` — массив товаров.

#### Интерфейс IOrder
Данные заказа, которые отправляются на сервер. Включает все данные покупателя, сумму и список идентификаторов купленных товаров.

```
interface IOrder extends IBuyer {
  total: number;
  items: string[];
}
```

`total` — общая стоимость заказа.  
`items` — массив `id` товаров из корзины.

#### Интерфейс IOrderResult
Ответ сервера на успешное оформление заказа.

```
interface IOrderResult {
  id: string;
  total: number;
}
```

`id` — идентификатор созданного заказа.  
`total` — списанная сумма.

## Модели данных

Модели данных отвечают только за хранение и изменение данных. Они не работают с DOM и не выполняют запросы к серверу.

#### Класс ProductsModel
Каталог товаров. Хранит все товары, доступные для покупки и товар, выбранный для подробного просмотра.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий, создаёт пустой каталог.

Поля класса:  
`events: IEvents` — брокер событий для уведомления об изменении данных.  
`items: IProduct[]` — массив всех товаров каталога.  
`preview: IProduct | null` — товар, выбранный для подробного отображения; `null`, если товар не выбран.

Методы класса:  
`setItems(items: IProduct[]): void` — сохраняет переданный массив товаров в каталог и генерирует событие `catalog:changed`.  
`getItems(): IProduct[]` — возвращает массив всех товаров.  
`getItem(id: string): IProduct | undefined` — возвращает товар по его `id` или `undefined`, если товар не найден.  
`setPreview(product: IProduct): void` — сохраняет товар для подробного отображения и генерирует событие `preview:changed`.  
`getPreview(): IProduct | null` — возвращает товар для подробного отображения.

#### Класс BasketModel
Корзина. Хранит товары, которые покупатель выбрал для покупки, и рассчитывает их количество и стоимость.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий, создаёт пустую корзину.

Поля класса:  
`events: IEvents` — брокер событий для уведомления об изменении данных.  
`items: IProduct[]` — массив товаров, добавленных в корзину.

Методы класса:  
`getItems(): IProduct[]` — возвращает массив товаров в корзине.  
`add(product: IProduct): void` — добавляет переданный товар в корзину, если его там ещё нет, и генерирует событие `basket:changed`.  
`remove(product: IProduct): void` — удаляет переданный товар из корзины и генерирует событие `basket:changed`.  
`clear(): void` — очищает корзину и генерирует событие `basket:changed`.  
`getTotal(): number` — возвращает общую стоимость товаров в корзине.  
`getCount(): number` — возвращает количество товаров в корзине.  
`has(id: string): boolean` — проверяет, находится ли товар с переданным `id` в корзине.

#### Класс BuyerModel
Покупатель. Хранит данные, которые покупатель указывает при оформлении заказа, и проверяет их корректность.

Конструктор:  
`constructor(events: IEvents)` — принимает брокер событий, создаёт модель с пустыми полями.

Поля класса:  
`events: IEvents` — брокер событий для уведомления об изменении данных.  
`payment: TPayment | ''` — способ оплаты; изначально пустая строка.  
`address: string` — адрес доставки.  
`email: string` — электронная почта.  
`phone: string` — телефон.

Методы класса:  
`setData(data: Partial<IBuyer>): void` — сохраняет переданные поля. Можно передать одно или несколько полей, значения остальных полей при этом не изменяются. Генерирует событие `buyer:changed`.  
`getData(): IBuyer` — возвращает все данные покупателя.  
`clear(): void` — сбрасывает все поля к пустым значениям и генерирует событие `buyer:changed`.  
`validate(): TBuyerErrors` — проверяет данные покупателя и возвращает объект с ошибками. Поле считается валидным, если оно не пустое. Для каждого пустого поля в объект добавляется текст ошибки, например:

```
{
  payment: 'Не выбран вид оплаты',
  email: 'Укажите email',
}
```

Если все поля заполнены, возвращается пустой объект.

## Слой коммуникации

#### Класс WebLarekApi
Отвечает за получение данных с сервера и отправку заказа. Использует композицию: объект для выполнения запросов передаётся в конструктор, поэтому класс не зависит от конкретной реализации `Api`.

Конструктор:  
`constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi` (экземпляр класса `Api`).

Поля класса:  
`api: IApi` — объект для выполнения запросов к серверу.

Методы класса:  
`getProducts(): Promise<IProductsResponse>` — выполняет `GET` запрос на эндпоинт `/product/` и возвращает объект с общим количеством товаров и массивом товаров.  
`createOrder(order: IOrder): Promise<IOrderResult>` — выполняет `POST` запрос на эндпоинт `/order/`, передавая данные покупателя, сумму и `id` выбранных товаров. Возвращает объект с `id` заказа и списанной суммой.

## Слой представления (View)

Все классы представления наследуются от базового класса `Component<T>`. Тексты интерфейса и классы-модификаторы, которые используют компоненты, вынесены в объект `settings` в файле `src/utils/constants.ts`. Каждый класс отвечает за свой блок разметки: находит нужные элементы в конструкторе, устанавливает слушатели событий и отображает переданные данные через сеттеры, которые вызываются в методе `render`. Классы представления не хранят данные и не содержат логики приложения. О действиях пользователя они сообщают через брокер событий или вызывают обработчик, полученный в конструкторе.

#### Типы данных для отображения
Новые типы построены на основе уже объявленных `IProduct` и `IBuyer`.

```ts
interface IHeader {
  counter: number;
}

interface IGallery {
  catalog: HTMLElement[];
}

interface IModal {
  content: HTMLElement;
}

interface ICardActions {
  onClick: (event: MouseEvent) => void;
}

type TCard = Pick<IProduct, 'title' | 'price'>;
type TCardCatalog = TCard & Pick<IProduct, 'image' | 'category'>;
type TCardPreview = TCardCatalog & Pick<IProduct, 'description'> & {
  buttonText: string;
  buttonDisabled: boolean;
};
type TCardBasket = TCard & {
  index: number;
};

interface IBasket {
  items: HTMLElement[];
  total: number;
  buttonDisabled: boolean;
}

interface IForm {
  valid: boolean;
  errors: string;
}

type TOrderForm = IForm & Pick<IBuyer, 'payment' | 'address'>;
type TContactsForm = IForm & Pick<IBuyer, 'email' | 'phone'>;

interface ISuccess {
  total: number;
}

type TFormChange = {
  field: keyof IBuyer;
  value: string;
};
```

`ICardActions` — обработчик действия пользователя, который передаётся в конструктор карточки. Внутри обработчика генерируется событие через брокер событий.  
`TFormChange` — данные события `form:change`: имя изменённого поля покупателя и новое значение.

#### Класс Header
Шапка страницы: кнопка открытия корзины и счётчик товаров в корзине.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` — принимает брокер событий и DOM-элемент шапки `.header`.

Поля класса:  
`basketButton: HTMLButtonElement` — кнопка открытия корзины.  
`counterElement: HTMLElement` — элемент счётчика товаров.

Методы класса:  
`set counter(value: number)` — выводит количество товаров в корзине.

При нажатии на кнопку корзины генерируется событие `basket:open`.

#### Класс Gallery
Каталог товаров на главной странице.

Конструктор:  
`constructor(container: HTMLElement)` — принимает DOM-элемент каталога `.gallery`.

Поля класса:  
Собственных полей нет: карточки выводятся в корневой элемент `container`.

Методы класса:  
`set catalog(items: HTMLElement[])` — выводит переданные карточки товаров.

#### Класс Modal
Модальное окно. Отображает переданный ему контент. От класса не наследуются другие классы: вся разметка, которая выводится в модальном окне, — самостоятельные компоненты.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` — принимает брокер событий и DOM-элемент модального окна `.modal`.

Поля класса:  
`closeButton: HTMLButtonElement` — кнопка закрытия.  
`contentElement: HTMLElement` — контейнер для содержимого.

Методы класса:  
`set content(value: HTMLElement)` — выводит переданное содержимое.  
`open(): void` — показывает модальное окно, добавляя модификатор `modal_active`.  
`close(): void` — скрывает модальное окно, удаляя модификатор `modal_active`.

При нажатии на кнопку закрытия или на область вне модального окна генерируется событие `modal:close`.

#### Класс Card
Абстрактный родительский класс для всех карточек товара. Содержит общий для всех карточек функционал: отображение названия и цены, а также метод вывода категории для дочерних карточек.

Конструктор:  
`constructor(container: HTMLElement)` — принимает DOM-элемент карточки.

Поля класса:  
`titleElement: HTMLElement` — название товара.  
`priceElement: HTMLElement` — цена товара.

Методы класса:  
`set title(value: string)` — выводит название товара.  
`set price(value: number | null)` — выводит цену товара в синапсах; если цены нет, выводит «Бесценно».  
`setCategory(element: HTMLElement, value: string): void` — защищённый метод: выводит категорию в переданный элемент и устанавливает модификатор фона из `categoryMap`. Используется в `CardCatalog` и `CardPreview`.

#### Класс CardCatalog
Карточка товара в каталоге. Наследуется от `Card`.

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardActions)` — принимает DOM-элемент из шаблона `#card-catalog` и обработчик нажатия на карточку.

Поля класса:  
`categoryElement: HTMLElement` — категория товара.  
`imageElement: HTMLImageElement` — изображение товара.

Методы класса:  
`set category(value: string)` — выводит категорию и устанавливает модификатор фона из `categoryMap`.  
`set image(value: string)` — выводит изображение товара.

При нажатии на карточку вызывается обработчик `actions.onClick`, в котором генерируется событие `card:select`.

#### Класс CardPreview
Карточка товара для подробного просмотра в модальном окне. Наследуется от `Card`.

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardActions)` — принимает DOM-элемент из шаблона `#card-preview` и обработчик нажатия на кнопку.

Поля класса:  
`categoryElement: HTMLElement` — категория товара.  
`imageElement: HTMLImageElement` — изображение товара.  
`descriptionElement: HTMLElement` — описание товара.  
`buttonElement: HTMLButtonElement` — кнопка покупки или удаления товара.

Методы класса:  
`set category(value: string)` — выводит категорию и устанавливает модификатор фона из `categoryMap`.  
`set image(value: string)` — выводит изображение товара.  
`set description(value: string)` — выводит описание товара.  
`set buttonText(value: string)` — выводит текст кнопки («Купить», «Удалить из корзины» или «Недоступно»).  
`set buttonDisabled(value: boolean)` — блокирует или разблокирует кнопку.

При нажатии на кнопку вызывается обработчик `actions.onClick`, в котором генерируется событие `card:buy`.

#### Класс CardBasket
Карточка товара в корзине. Наследуется от `Card`.

Конструктор:  
`constructor(container: HTMLElement, actions?: ICardActions)` — принимает DOM-элемент из шаблона `#card-basket` и обработчик нажатия на кнопку удаления.

Поля класса:  
`indexElement: HTMLElement` — порядковый номер товара в корзине.  
`deleteButton: HTMLButtonElement` — кнопка удаления товара.

Методы класса:  
`set index(value: number)` — выводит порядковый номер товара.

При нажатии на кнопку удаления вызывается обработчик `actions.onClick`, в котором генерируется событие `card:delete`.

#### Класс Basket
Содержимое корзины.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` — принимает брокер событий и DOM-элемент из шаблона `#basket`.

Поля класса:  
`listElement: HTMLElement` — список товаров.  
`totalElement: HTMLElement` — общая стоимость.  
`orderButton: HTMLButtonElement` — кнопка оформления заказа.

Методы класса:  
`set items(value: HTMLElement[])` — выводит карточки товаров; если массив пустой, выводит надпись «Корзина пуста».  
`set total(value: number)` — выводит общую стоимость товаров.  
`set buttonDisabled(value: boolean)` — блокирует или разблокирует кнопку оформления.

При нажатии на кнопку «Оформить» генерируется событие `basket:order`.

#### Класс Form
Абстрактный родительский класс для форм оформления заказа. Содержит общий для всех форм функционал: кнопку отправки, вывод ошибок, отслеживание ввода и отправки формы.

Конструктор:  
`constructor(events: IEvents, container: HTMLFormElement)` — принимает брокер событий и DOM-элемент формы.

Поля класса:  
`submitButton: HTMLButtonElement` — кнопка отправки формы.  
`errorsElement: HTMLElement` — элемент для вывода ошибок.

Методы класса:  
`set valid(value: boolean)` — разблокирует кнопку отправки, если `true`, и блокирует, если `false`.  
`set errors(value: string)` — выводит текст ошибок.

При вводе данных в поле формы генерируется событие `form:change` с объектом `{ field, value }`, где `field` — имя поля, `value` — введённое значение. При отправке формы генерируется событие `<имя формы>:submit`: `order:submit` для формы `order` и `contacts:submit` для формы `contacts`.

#### Класс OrderForm
Первый шаг оформления заказа: способ оплаты и адрес доставки. Наследуется от `Form`.

Конструктор:  
`constructor(events: IEvents, container: HTMLFormElement)` — принимает брокер событий и DOM-элемент из шаблона `#order`.

Поля класса:  
`cardButton: HTMLButtonElement` — кнопка оплаты онлайн.  
`cashButton: HTMLButtonElement` — кнопка оплаты при получении.  
`addressInput: HTMLInputElement` — поле адреса доставки.

Методы класса:  
`set payment(value: TPayment | '')` — выделяет кнопку выбранного способа оплаты модификатором `button_alt-active`.  
`set address(value: string)` — выводит адрес в поле ввода.

При нажатии на кнопку способа оплаты генерируется событие `form:change` с объектом `{ field: 'payment', value }`, где `value` — `'card'` или `'cash'`.

#### Класс ContactsForm
Второй шаг оформления заказа: почта и телефон. Наследуется от `Form`.

Конструктор:  
`constructor(events: IEvents, container: HTMLFormElement)` — принимает брокер событий и DOM-элемент из шаблона `#contacts`.

Поля класса:

Методы класса:

`set phone(value: string)` — выводит телефон в поле ввода.

#### Класс Success
Сообщение об успешном оформлении заказа.

Конструктор:  
`constructor(events: IEvents, container: HTMLElement)` — принимает брокер событий и DOM-элемент из шаблона `#success`.

Поля класса:  
`descriptionElement: HTMLElement` — текст со списанной суммой.  
`closeButton: HTMLButtonElement` — кнопка закрытия.

Методы класса:  
`set total(value: number)` — выводит списанную сумму.

При нажатии на кнопку «За новыми покупками!» генерируется событие `success:close`.

## События

#### События моделей данных
`catalog:changed` — изменился массив товаров каталога (`ProductsModel.setItems`).  
`preview:changed` — изменился товар, выбранный для подробного просмотра (`ProductsModel.setPreview`).  
`basket:changed` — изменилось содержимое корзины (`BasketModel.add`, `remove`, `clear`).  
`buyer:changed` — изменились данные покупателя (`BuyerModel.setData`, `clear`).

#### События представлений
`card:select` — выбрана карточка товара для просмотра; передаёт товар.  
`card:buy` — нажата кнопка в карточке подробного просмотра; передаёт товар.  
`card:delete` — нажата кнопка удаления товара в корзине; передаёт товар.  
`basket:open` — нажата кнопка открытия корзины.  
`basket:order` — нажата кнопка оформления заказа в корзине.  
`order:submit` — отправлена форма способа оплаты и адреса, переход ко второй форме.  
`contacts:submit` — отправлена форма почты и телефона, оплата заказа.  
`form:change` — изменены данные в форме; передаёт объект `{ field, value }`.  
`modal:close` — нажата кнопка закрытия модального окна или область вне его.  
`success:close` — нажата кнопка закрытия сообщения об успешном заказе.

## Презентер

Приложение состоит из одной страницы, поэтому для него используется один презентер. Код презентера не вынесен в отдельный класс и находится в основном скрипте приложения `src/main.ts`.

Презентер создаёт брокер событий, экземпляр класса для работы с API, модели данных и компоненты представления, а затем связывает их между собой через обработчики событий. Сам презентер события не генерирует. Генерация событий есть только внутри обработчиков, которые презентер передаёт в конструкторы карточек: эти обработчики вызывает компонент представления в ответ на действие пользователя.

Презентер получает данные из моделей с помощью их методов и подготавливает их для компонентов представления. Компоненты представления перерисовываются только в двух случаях: при обработке события модели данных об изменении данных или при открытии модального окна.

При запуске приложения презентер запрашивает с сервера массив товаров и сохраняет его в модели каталога.

#### Вспомогательные функции
`getBasketCards(): HTMLElement[]` — создаёт карточки товаров для корзины из данных модели корзины.  
`getBasketData(): IBasket` — подготавливает данные для отрисовки корзины: карточки товаров, общую стоимость и признак блокировки кнопки оформления.  
`getOrderFormData(): TOrderForm` — подготавливает данные для формы способа оплаты и адреса: значения полей, признак валидности и текст ошибок.  
`getContactsFormData(): TContactsForm` — подготавливает данные для формы почты и телефона: значения полей, признак валидности и текст ошибок.

#### Обработка событий моделей данных
`catalog:changed` — создаёт карточки для всех товаров каталога и выводит их на главной странице.  
`preview:changed` — создаёт карточку подробного просмотра выбранного товара и открывает её в модальном окне. Текст кнопки зависит от состояния товара: «Купить», «Удалить из корзины», если товар уже в корзине, или «Недоступно», если у товара нет цены (в этом случае кнопка заблокирована).  
`basket:changed` — обновляет счётчик товаров в шапке и содержимое корзины.  
`buyer:changed` — обновляет значения полей, ошибки валидации и состояние кнопок в обеих формах оформления заказа.

#### Обработка событий представлений
`card:select` — сохраняет выбранный товар в модели каталога как товар для подробного просмотра.  
`card:buy` — добавляет товар в корзину или удаляет его, если товар уже в корзине, и закрывает модальное окно.  
`card:delete` — удаляет товар из корзины.  
`basket:open` — открывает корзину в модальном окне.  
`basket:order` — открывает в модальном окне форму способа оплаты и адреса.  
`form:change` — сохраняет изменённое поле в модели покупателя.  
`order:submit` — открывает в модальном окне форму почты и телефона.  
`contacts:submit` — собирает данные заказа из моделей покупателя и корзины и отправляет их на сервер. После успешного ответа очищает корзину и данные покупателя и показывает сообщение об успешном оформлении заказа.  
`success:close` — закрывает модальное окно.  
`modal:close` — закрывает модальное окно.
